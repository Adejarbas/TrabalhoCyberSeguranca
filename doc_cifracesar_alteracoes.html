1. Visão Geral do Projeto

O sistema implementa a Cifra de César, uma das técnicas de criptografia mais antigas, onde cada caractere é deslocado por um número fixo de posições no alfabeto. O projeto possui:

  • 4 telas: Login, Cadastro, Criptografar e Descriptografar
  • Autenticação JWT para proteger as rotas
  • Hash de uso único como chave privada para descriptografia
  • Banco de dados SQLite para persistência

4. Autenticação com JWT

O JWT (JSON Web Token) é usado para garantir três pilares de segurança:

  • Autenticidade: Somente o servidor pode gerar tokens válidos
  • Integridade: O token não pode ser alterado sem ser invalidado
  • Confidencialidade: Os dados do usuário ficam protegidos no token

4.1. Como funciona o fluxo

  1. Usuário faz login com usuário e senha
  2. Servidor valida a senha com bcrypt e gera um token JWT (válido por 2 horas)
  3. Frontend armazena o token no localStorage
  4. Em cada requisição protegida, o token é enviado no header Authorization
  5. O middleware verificarToken valida o token antes de processar a requisição

Trecho do código - Middleware JWT (server/middleware/auth.cjs):

// Middleware que verifica se o usuário está autenticado
function verificarToken(req, res, next) {
  // Pega o token do cabeçalho Authorization (formato: "Bearer <token>")
  const authHeader = req.headers['authorization'];
  const token = authHeader && authHeader.split(' ')[1];

  if (!token) {
    return res.status(401).json({ erro: 'Token não fornecido.' });
  }

  try {
    // Verifica se o token é válido e não expirou
    const decoded = jwt.verify(token, SEGREDO_JWT);
    req.usuario = decoded;
    next();
  } catch (err) {
    return res.status(403).json({ erro: 'Token inválido ou expirado.' });
  }
}

4.2. Geração do Token no Login

// Compara a senha digitada com o hash armazenado
const senhaValida = bcrypt.compareSync(senha, user.senha);

// Gera o token JWT com validade de 2 horas
const token = jwt.sign(

4.3. Senha protegida com Bcrypt

As senhas nunca são armazenadas em texto puro. Usamos o bcrypt para gerar um hash seguro:

// Criptografa a senha usando bcrypt (hash de 10 rounds)
const senhaHash = bcrypt.hashSync(senha, 10);

5. Cifra de César - Implementação

A Cifra de César desloca cada caractere do texto por um número fixo de posições. O nosso alfabeto inclui letras (a-z) e números (0-9), totalizando 36 caracteres.

5.1. Exemplo Visual

OriginalPasso +3Resultado
aa → b → c → dd
hh → i → j → kk
11 → 2 → 3 → 44
zz → 0 → 1 → 22 (volta ao início)

Trecho do código (server/routes/crypto.cjs):

// Alfabeto: letras minúsculas + números (a-z, 0-9)
const ALFABETO = 'abcdefghijklmnopqrstuvwxyz0123456789';

// Função que aplica a Cifra de César
function cifrarCesar(texto, passo) {
  let resultado = '';

  for (let i = 0; i < texto.length; i++) {
    const char = texto[i].toLowerCase();
    const indice = ALFABETO.indexOf(char);

    if (indice !== -1) {
      // Calcula nova posição com deslocamento circular
      let novoIndice = (indice + passo) % ALFABETO.length;
      if (novoIndice < 0) novoIndice += ALFABETO.length;
      resultado += ALFABETO[novoIndice];
    } else {
      // Mantém caracteres fora do alfabeto (espaços, etc.)
      resultado += char;
    }
  }
  return resultado;
}

// Para descriptografar, basta inverter o passo
function decifrarCesar(texto, passo) {
  return cifrarCesar(texto, -passo);
}
Por que deslocamento circular? Usamos o operador % (módulo) para que quando o deslocamento ultrapasse o fim do alfabeto, ele "volte ao início". Ex: com passo 3, a letra "z" (posição 25) vai para "2" (posição 28 % 36 = 28, que corresponde ao "2").

6. Sistema de Hash (Chave Privada)

Ao criptografar uma mensagem, o sistema gera um hash aleatório de 32 caracteres que funciona como chave privada. Esse hash é de uso único.

6.1. Fluxo de Criptografia

  1. Usuário digita mensagem e passo
  2. Backend aplica a Cifra de César
  3. Backend gera um hash aleatório com crypto.randomBytes
  4. Hash, passo e mensagem criptografada são salvos no banco com usado = 0
  5. Hash é exibido ao usuário como chave privada
// Gera hash aleatório de 32 caracteres hexadecimais
function gerarHash() {
  return crypto.randomBytes(16).toString('hex');
}

// Salva no banco: hash, passo e mensagem criptografada
const stmt = db.prepare(
  'INSERT INTO mensagens (usuario_id, hash_chave, passo, mensagem_criptografada, usado) VALUES (?, ?, ?, ?, 0)'
);
stmt.run(req.usuario.id, hashChave, passoNumero, mensagemCriptografada);

6.2. Fluxo de Descriptografia (Hash de uso único)

  1. Usuário informa a mensagem criptografada e o hash
  2. Sistema busca o hash no banco
  3. Verifica se o hash existe e se não foi usado
  4. Se válido: descriptografa e marca usado = 1
  5. Se inválido ou já usado: retorna mensagem de erro
// Busca o hash no banco de dados
const registro = db.prepare('SELECT * FROM mensagens WHERE hash_chave = ?').get(hashChave);

// Verifica se o hash já foi usado
if (registro.usado) {
  return res.status(400).json({
    erro: 'Este hash já foi utilizado! Cada hash só pode ser usado uma única vez.'
  });
}

// Descriptografa e marca como usado
const mensagemOriginal = decifrarCesar(mensagemCriptografada, registro.passo);
db.prepare('UPDATE mensagens SET usado = 1 WHERE hash_chave = ?').run(hashChave);
Segurança: Cada hash só pode ser usado UMA vez. Após a descriptografia, ele é marcado como usado = 1 no banco de dados, impedindo reutilização.

7. Frontend (React + Vite)

7.1. Rotas Protegidas

As telas de Criptografar e Descriptografar só podem ser acessadas por usuários logados:

// Componente que protege rotas
function RotaProtegida({ children }) {
  const { token } = useAuth();
  // Se não tem token, redireciona para o login
  return token ? children : <Navigate to="/login" />;
}

// Uso nas rotas:
<Route path="/criptografar" element={
  <RotaProtegida><Criptografar /></RotaProtegida>
} />

7.2. Contexto de Autenticação

O estado de login é gerenciado globalmente usando React Context API:

// Salva token no localStorage para manter login ao recarregar
const login = (novoToken, nomeUsuario) => {
  localStorage.setItem('token', novoToken);
  localStorage.setItem('usuario', nomeUsuario);
  setToken(novoToken);
  setUsuario(nomeUsuario);
};

7.3. Comunicação com a API

O frontend envia o token JWT em todas as requisições autenticadas:

const resposta = await fetch('http://localhost:3001/api/criptografar', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
